The problem

I train almost every day and have access to a gym, a pool, running routes, and a huge library of saved Garmin workouts — but every morning I still had to decide, from scratch, what today's session should actually be. Garmin's own "training status" widget gives a label; it doesn't reason about my week, my goals, or the fact that I saw a physio yesterday.

I didn't want a rules engine (if readiness < 30: rest) — that can't weigh trade-offs the way a real coach does. I wanted an AI layer that reads the same data a coach would, and tells me what to do about it, in plain language, with a reason I can push back on.

Design decisions

Why it's built this way

Self-hosted, not a service

No central server ever holds your Garmin password. There's no public Garmin API for personal use, so the only path is a login-based library — and I wasn't willing to build a hosted product that stores other people's credentials. Each user runs their own copy, with their own bot, on their own AWS account.

Second opinion, not a verdict

Garmin already computes its own training-readiness score. hakigains forms its own recommendation first, then explicitly reconciles with Garmin's — agreeing, or naming the disagreement and why. Two coaches you can compare, not one black box.

Profile you own, not a prompt you edit

Goals, preferred activities, and constraints live in a plain-language config.yaml — free-form sections, your own words. The coaching logic never hardcodes anyone's specific situation; runtime dials (intensity_bias, trend window) are changeable live, from the bot itself.

A workflow, not an agent

The daily briefing is a deterministic pipeline with one LLM reasoning step — predictable, cheap, easy to debug. Only the interactive side (asking it questions) behaves agent-like, and it's hard-gated to my own Telegram chat ID; strangers can message the bot, but it never touches my data.

Architecture

One core, two entry points

The same gated logic runs the scheduled cron and the live bot, so neither can accidentally skip the security gate.

EventBridge (daily)  ─►  ingest ─► reason ─► deliver → Telegram
Telegram webhook     ─►  bot/core (chat-ID gated) ─► /brief · /set · Q&A

secrets  AWS Secrets Manager — Garmin creds · LLM key · bot token
state    S3 — Garmin auth token + settings, synced across cold starts
brain    LLM behind a provider interface — Azure OpenAI today, Bedrock/Claude next
deploy   AWS SAM · container-image Lambda · ap-southeast-1
Stack
◈Python 3.12 ◈garminconnect ◈Azure OpenAI → Bedrock ◈Telegram Bot API ◈AWS Lambda + EventBridge ◈Secrets Manager · S3 ◈AWS SAM
